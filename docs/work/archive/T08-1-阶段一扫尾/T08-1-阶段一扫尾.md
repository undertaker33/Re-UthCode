## 一、Spec

### 1. 背景

当前 `PLAN` 同时承担只读安全边界和 Plan 提交信号。任何 Provider 普通 final 都会被完成前 Hook 转换为 Plan Review，因此只读问答、文件定位、代码解释和调查结论也无法正常结束。T08 已具备 `PlanState`、typed Plan Review、revision、同 Turn 暂停恢复、批准后切换 `DEFAULT` 以及 TUI/Headless 投影，本任务只补上明确的 Plan 提交协议，不重建规划系统。

当前 `/permission` 只修改内存 `AgentRun`，每次启动固定回到 `default`；模型选择则已有用户配置原子写回。用户已决定让安全的权限默认值成为用户级偏好，同时保持 `full_access` 仅当前 Run 有效。

外部产品事实用于校准边界：Gemini CLI 使用显式 `exit_plan_mode` 提交正式 Plan，并将安全的默认审批模式写入设置，但 YOLO 只能由命令行显式开启；Claude Code 将默认权限模式、持久规则和会话授权分别管理；OpenAI 官方建议区分只读回答/规划与真正执行动作的授权边界。

参考：

- [Gemini CLI planning tools](https://geminicli.com/docs/tools/planning/)
- [Gemini CLI settings](https://geminicli.com/docs/cli/settings/)
- [Claude Code CLI](https://docs.anthropic.com/en/docs/claude-code/cli-usage)
- [OpenAI model guidance](https://developers.openai.com/api/docs/guides/latest-model)

### 2. 目标

- 保留 `PLAN` 的强制只读工具边界，但允许普通只读 final 直接完成 Turn。
- 只有模型显式提交准备在获批后实施的 Plan 时，才创建或替换 `PlanState` 并进入现有 typed Plan Review。
- 保持修订、批准、取消、同 Turn 恢复、批准后切换 `DEFAULT` 与唯一 Agent Loop 的现有语义。
- 将用户选择的安全 Permission 默认值写入用户配置，并在下次启动创建 Run 时生效。
- `full_access` 只改变当前 Run，不写入配置、不成为后续 Run 默认值，并在 TUI 底部状态栏持续使用警告色显示。

### 3. 能力清单

#### Task 1 — 显式 Plan 提交控制协议

新增 Provider 无关的 `ProposePlan` Core 控制 Tool。它只在 `PLAN` 中可见，承载一份非空自然语言 Plan；revision 由 Core 权威计算，模型不能指定。

#### Task 2 — Plan Review 触发与恢复语义

普通 `PLAN` final 直接完成；合法 `ProposePlan` 调用才产生 `PlanState`、`PlanProposed` 和 `PLAN_REVIEW_REQUIRED`。修订后仍在同一 Turn 的 `PLAN` 中重新提交；批准后在公开恢复前切换当前 Run/Turn 为 `DEFAULT` 并继续实施。

#### Task 3 — 用户级 Permission 默认值

用户配置保存 `default` 或 `auto` 作为新 Application/Run 的默认 Permission Mode。项目配置不能提供或覆盖该字段。`/permission default|auto` 必须先原子写回成功，再更新 Application 默认值与当前 Run；写回失败时三者均保持旧值。

#### Task 4 — `full_access` 临时态与警告投影

`/permission full_access` 仅修改当前 Run，不写回用户配置，也不改变后续 Run 的安全默认值。TUI 底部状态栏仅将 `permission: full_access` 片段显示为现有警告色，其他状态栏内容保持原样。

#### Task 5 `[接入主流程]` — Application、Headless 与 TUI 统一接线

将两项能力接入正式 `create_application -> create_run -> start_turn -> AgentLoop` 链路，删除旧的“任意 PLAN final 强制 Review”路径和 TUI 权限切换旁路。

#### Task 6 `[端到端验证]` — Plan 与 Permission 重启边界验收

使用离线 Provider、真实 Application 组合、临时用户配置和 TUI 投影验证普通 PLAN 回答、正式 Plan 审批实施、安全权限写回、重载生效、失败原子性与 `full_access` 临时态。

#### Task 7 `[遗留负担清理]` — 旧完成 Hook 与重复状态收口

删除被替代的完成触发、重复权限修改和无调用方兼容入口；确认未引入 Session、第二 Agent Loop、通用控制 Tool registry 或 Behavior Mode 持久化。

### 4. 非功能要求

- 保持 `interfaces -> application -> core`，由 Application 组合 Integrations；Provider SDK 类型不得进入 Core/Application。
- `ProposePlan` 是固定 Core 控制协议，不进入普通 Tool 实际执行、Permission 或 OS 进程边界，不新增第二 Agent Loop。
- PLAN 非只读普通 Tool 仍在 Permission 前 fail-closed；`full_access` 不能绕过该边界。
- 每个 Provider `ToolCall` 必须恰好得到一个 `ToolResult`。Plan 审批暂停、修订、批准和取消时不得遗留未闭合 call ID。
- `ProposePlan` 与其他 ToolCall 同批时必须采用单一、确定且 fail-closed 的语义；不得在控制转换边界执行同批普通 Tool 的潜在副作用。实现以“`ProposePlan` 必须是该响应唯一 ToolCall，否则整批受控拒绝且不创建 Plan”为冻结规则。
- 用户配置只允许安全 Permission 默认值；项目配置不得静默设置权限模式。
- 配置写回使用现有 TOMLKit、同目录临时文件和 `os.replace` 原子路径，保留注释、表顺序及无关字段。
- 不新增运行时依赖。

### 5. 设计骨架

```text
PLAN Provider response
├─ ordinary final
│    -> accept final
│    -> complete Turn
└─ ProposePlan(plan)
     -> validate sole control ToolCall + payload
     -> create/replace PlanState with Core revision
     -> emit PlanProposed
     -> typed Plan Review pause
          ├─ REVISE -> close call -> real user feedback -> remain PLAN -> same Turn
          ├─ APPROVE -> close call -> approve state -> switch DEFAULT -> same Turn execute
          └─ CANCEL -> cancellation wins -> close pending call -> terminal cancel
```

```text
startup
  -> load user default_permission_mode (default|auto; omitted => default)
  -> create Application default
  -> create AgentRun with that default

/permission default|auto
  -> atomically write user config
  -> update Application default
  -> update current idle/active Run strategy for subsequent tool decisions

/permission full_access
  -> current Run only
  -> no config write / no Application default change
  -> TUI status warning colour
```

### 6. 已确认决策

1. `/new` 不属于本任务，不设计也不实施。
2. 普通 PLAN final 是只读回答，不触发 Plan Review。
3. 只有准备在获批后继续实施的正式方案才调用 `ProposePlan`；纯方案讨论、只读调查、文件定位、代码解释和用户只要求 Plan 文本时均使用普通 final。
4. Permission 默认值只存用户配置；项目配置禁止设置。
5. `default`、`auto` 同时修改当前 Run 和下次启动默认值；持久化失败时当前 Run 不变。
6. `full_access` 仅当前 Run，不持久化；底部 `permission: full_access` 使用警告色。
7. Behavior Mode 不持久化。`/plan`、`/do` 仍只影响当前 Run；Plan 获批只把当前活动 Turn/Run 切到 `DEFAULT`。
8. 当前没有 Session 恢复；不得设计“重启后恢复已批准 Plan”。

### 7. 能力欠账

本任务回补 `T08 Plan Mode / Plan Review` 的显式提交协议欠账。没有新增能力欠账。

持久 Session、跨进程 Plan/批准事实恢复、跨 Turn Todo/Plan、Context Compaction 后状态恢复仍按原欠账保留；它们不是本任务前置条件。

### 8. Out of Scope

- `/new`、`/resume`、持久 Session、会话列表、跨进程 Run/Turn/Plan 恢复。
- Behavior Mode 持久化、项目级 Permission 默认值、`full_access` 持久化。
- Permission Rule 的新增持久授权语义；现有 Session Grant 生命周期不变。
- Plan 文件、Plan Artifact、Plan 到 Todo 自动编译、长期 Plan Persistence。
- Context Compiler、Memory、Skill、MCP、动态 Tool、动态 Hook registry。
- OS Sandbox、Subagent、Multi-Agent、Worktree 产品能力。
- 新 Hook 生命周期点、通用控制 Tool registry、事件总线或工作流引擎。

### 9. 验收标准

1. PLAN 普通 final 可从 Headless 与 TUI 正常完成，不产生 PlanState、PlanProposed 或 Plan Review pause。
2. `ProposePlan` 仅在 PLAN 请求中可见；DEFAULT、非法参数、空 Plan、额外参数和混合 Tool batch 均受控失败且不创建 PlanState。
3. 合法 Plan 的 revision、REVISE、APPROVE、CANCEL 保持同一 run/turn/handle；所有原始 ToolCall ID 恰好闭合一次。
4. APPROVE 在公开 `TurnResumed` 前切换当前模式为 DEFAULT，并继续同 Turn 实施；REVISE 保持 PLAN。
5. 用户配置缺省权限为 `default`；合法 `default|auto` 可加载并注入新 Run；项目配置出现该字段硬失败。
6. `/permission default|auto` 写回成功后当前 Run 与重载后的新 Application 一致；写回失败时配置、Application 默认值、当前 Run 均不改变。
7. `/permission full_access` 不改变用户文件和 Application 默认值，新 Run 仍使用原安全默认值；TUI 底部权限片段为警告色。
8. Plan 只读 Hook、Permission Guard/Policy/Strategy、Session Grant、Todo Completion Gate、Steering、AskUser、暂停恢复和取消既有测试不回归。
9. 架构测试、全量测试、compileall、pip check、UTF-8 guard 与 diff check 通过。
