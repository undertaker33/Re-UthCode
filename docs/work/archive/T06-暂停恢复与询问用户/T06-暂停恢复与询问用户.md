## 2. 当前实现基线

### 2.1 当前运行链路

```text
CLI / TUI / Headless
        ↓
UthCodeApplication.create_run()
        ↓
AgentRun.start_turn()
        ↓
TurnHandle.events() / cancel() / result()
        ↓
Core AgentLoop
        ↓
Provider stream → Tool FIFO → Provider stream
        ↓
completed / failed / cancelled
```

当前链路已经具备：

- 一个内存 Run 内多个 Turn；
- 同一 Run 同时最多一个活动 Turn；
- Provider、Model 与 Tool definitions 按 Turn 固定；
- 严格 FIFO Tool Batch；
- 流式 AgentEvent；
- 用户取消、Provider 错误、预算终止和内部错误终态；
- CLI、TUI 与 Headless 共用同一 Agent Core。

### 2.2 当前状态语义

当前 `RunStatus`：

```text
running
completed
failed
cancelled
```

当前 `TurnHandle.cancel()` 会把当前 Turn 收束为 `cancelled / user_cancelled`；`NetworkError`、`RateLimitError` 与其他 ProviderError 会把当前 Turn 收束为 `failed / provider_error`。

T06 **不得**向 `RunStatus` 增加 `paused`。暂停只属于当前活动 Turn，是与 Run 生命周期正交的临时控制状态：

```text
AgentRun / RunStatus：保持 running
当前活动 Turn：running → pausing → paused → running
pending_pause：None → PauseRequest → None
```

| Turn 控制状态 | 是否终态 | 能否在同一进程继续同一 Turn | 典型来源 |
| --- | --- | --- | --- |
| `pausing` | 否 | 是 | 已收到暂停请求，正在等待 Provider 或 Tool 安全边界 |
| `paused` | 否 | 是 | 用户主动暂停、等待用户回答、可重试网络异常 |
| `cancelled` | 是 | 否 | 用户明确取消、界面退出时终止当前 Turn |
| `failed` | 是 | 否 | 不可恢复 Provider 错误、协议错误、内部错误 |
| `completed` | 是 | 否 | 当前 Turn 正常完成 |

`pausing/paused` 通过当前 Turn 的 `pending_pause` 与 `TurnPausing/TurnPaused/TurnResumed` 事件表达，不写入 Run 级状态。暂停期间 `AgentRun` 仍可处理该 Turn 的 resume、answer、retry 和 cancel 控制操作，只是因为“一次最多一个活动 Turn”的既有约束，不能同时启动第二个 Turn。

不得通过 `failed` 或 `cancelled` 模拟暂停，也不得把恢复包装成新 Turn。

### 2.3 当前 Tool 执行边界

当前 `ToolExecutor.execute_call()` 要求每个 ToolCall 最终返回同 ID 的 `ToolResultPart`。Agent Loop 在一个 Tool Batch 中逐个 await Tool，并在整个 Batch 闭合后把 ToolResult message 交给下一轮 Provider。

因此：

- `AskUserQuestion` 不能是在 Integration 内等待 UI Future 的普通 Tool；
- Agent Loop 必须在该 ToolCall 位置暂停；
- 恢复后答案转换为原 `tool_call_id` 的 `ToolResultPart`；
- 该 ToolCall 后面的 ToolCall 在恢复前不得执行；
- 已完成的前序 ToolResult 必须保留且不得重放；
- 本任务不需要给普通 Tool 增加 replayability、journal 或恢复元数据。

### 2.4 当前 Provider 边界

`core/provider.py` 已提供：

```text
CancellationToken
NetworkError
RateLimitError
AuthenticationError
ProviderConfigurationError
InvalidProviderResponseError
GenerationCancelled
validated_provider_stream()
```

`validated_provider_stream()` 只有在收到唯一权威 `GenerationCompleted` 并正常 EOF 后才公开 terminal。网络中断前的部分文本、reasoning delta 和未完成 Usage 不属于权威 RunState。

本任务可以在同一进程内从最后权威 conversation 重新发起当前 Provider iteration，但不得：

- 提交部分流式消息；
- 新增第二套 Provider DTO；
- 把 SDK 异常对象带入 Core；
- 自动无限重试。

### 2.5 当前 Interface 行为

当前 TUI：

- 双 Esc 取消当前 Turn；
- Ctrl+C 退出 UthCode；
- 活动 Turn 期间拒绝提交新消息；
- 只消费 Application 公开事件；
- 使用主缓冲区 scrollback，不进入 alternate screen。

当前 `uthcode exec`：

## 3. 当前任务目标

### 3.1 最终交付

T06 完成后必须具备：

1. 当前 Turn 具备非终态的 `pausing/paused` 控制阶段与明确暂停原因，且 Run 级状态保持不变；
2. 用户主动暂停当前 Turn，并在同一进程内恢复同一 Turn；
3. `AskUserQuestion` 控制工具，支持结构化文本、单选和多选问题；
4. 用户答案关联原 `pause_id / turn_id / tool_call_id / question_id`；
5. 答案作为原 ToolCall 的 `ToolResultPart` 回填，随后继续原 FIFO Batch；
6. `NetworkError` 与 `RateLimitError` 转为同进程可恢复暂停；
7. Authentication、配置错误和无效 Provider 响应仍然失败；
8. 用户主动暂停 Provider 时丢弃未提交 delta，恢复后重试同一 iteration；
9. 用户主动暂停 Tool Batch 时等待当前普通 ToolCall 到安全边界，再暂停于下一执行位置；
10. Headless 调用方不依赖 TUI 即可检查 pending 并提交恢复响应；
11. TUI 可以暂停、恢复、回答问题和取消当前 Turn；
12. `uthcode exec` 遇到 paused 时不会无限等待，也不会输出伪 final；
13. Ctrl+C、async task cancellation、进程退出或崩溃后不提供恢复；
14. 全量正常、错误、暂停、恢复、问答、网络异常和架构回归测试。

### 3.2 明确不交付

本任务不实现：

- Session、会话持久化、Transcript 持久化、上下文历史存储；
- 进程退出、崩溃、强制结束、断电后的恢复；
- 启动时发现未完成 Turn；
- 恢复文件、数据库、Journal、Checkpoint、事件溯源；
- Tool replayability、未知副作用审查或跨进程 Tool 重放；
- 任意 Python 调用栈、协程局部变量或第三方 Tool 的透明恢复；
- Provider 自动无限重试、后台计时器或退避调度器；
- secret/password 问题、密码遮罩或答案加密；
- Permission Ask、Plan Mode、Todo、MCP elicitation 或通用交互框架；
- 并行 Tool Batch；
- 新 Slash Command、会话列表或恢复命令；
- 对旧 UthCode/MewCode checkpoint 的读取或迁移。

### 3.3 最小调用链

> **不可违反的层级边界**：双 Esc、AskUser 和网络异常都只暂停当前活动 Turn。它们不得暂停 `AgentRun`、不得冻结 Run 级控制通道、不得阻止 Interface 向该 Turn 提交回答、重试、继续或取消操作。

#### 用户主动暂停

```text
Interface / Headless
        ↓
TurnHandle.pause()
        ↓
Application 设置当前 Turn 的 pause request
        ↓
Provider：协作停止当前非权威流
Tool：当前 ToolCall 正常收口后停止推进
        ↓
Core 生成 TurnPaused + PauseRequest
        ↓
TurnHandle.resume(ResumeTurnResponse)
        ↓
Core 从内存 continuation 继续同一 Turn
```

#### 询问用户

```text
Provider 返回 AskUserQuestion ToolCall
        ↓
Core 校验问题并暂停于该 tool_call_id
        ↓
UserInputRequested / TurnPaused
        ↓
TUI 或 Headless 提交 UserInputResponse
        ↓
Core 生成同 ID ToolResultPart
        ↓
继续原 FIFO Tool Batch
```

#### 网络异常

```text
Provider stream 抛出 NetworkError / RateLimitError
        ↓
Core 保留最后权威 conversation 与当前 iteration
        ↓
TurnPaused(provider_unavailable)
        ↓
RetryProviderResponse 或 turn.cancel()
        ↓
同进程重新请求当前 iteration / 终态取消
```

### 3.4 三类暂停场景

#### A. 用户主动暂停

- `TurnHandle.pause()` 只请求暂停，不等同于 cancel；
- Provider 阶段可以停止当前非权威流，恢复后从该 iteration 的请求边界重试；
- Tool 阶段不得为了暂停强制中断当前普通 ToolCall；
- 当前 ToolCall 完成后，先保存其内存结果，再在下一个 ToolCall 前暂停；
- 暂停后 `AgentRun` 仍占用活动 Turn 槽位；
- 同一进程退出后该暂停状态丢失，不提供恢复承诺。

#### B. 等待用户回答

- 模型调用 `AskUserQuestion`；
- Core 校验结构化问题并发布 `UserInputRequested`；
- Turn 进入 `paused / user_input_required`；
- 用户回答后生成原 `tool_call_id` 的 ToolResult；
- 继续执行原 Batch 中尚未执行的后续 ToolCall；
- 不设置固定等待超时；
- 用户取消 Turn 时，为当前 AskUser 与尚未执行的同批 ToolCall 生成确定性取消结果，再进入 cancelled。

#### C. 网络异常

- 仅 `NetworkError` 与 `RateLimitError` 进入 `paused / provider_unavailable`；
- 暂停点是当前 Provider iteration 开始前的最后权威 RunState；
- Retry 不重复增加 iteration；
- 部分 text/reasoning delta 与未完成 Usage 不进入 conversation；
- 用户可以 Retry 或 CancelTurn；
- 用户退出程序后任务丢失，不生成持久续点。

### 3.5 程序中断边界

以下情况不属于 pause/resume：

- Ctrl+C 退出；
- TUI shutdown；
- `asyncio.Task.cancel()` 导致执行任务结束；
- Python 进程崩溃；
- 强制结束、终端关闭或断电。

处理原则：

- 正常可控退出时尽力调用 `TurnHandle.cancel()`，按 T05 取消协议闭合当前 Turn；
- 进程直接消失时不承诺 ToolResult 补偿或 RunState 保存；
- 新进程启动后创建全新内存 Run；
- 不扫描、恢复或提示上次未完成任务；
- 相关持久化能力必须等待上下文工程统一设计。

## 4. 历史要求处理表

| 来源要求或历史行为 | 处理 | 新版落实方式 | 原因 | 验收方式 |
| --- | --- | --- | --- | --- |
| 用户主动暂停后继续当前任务 | 保留 | 当前 Turn 的 `pending_pause` + `TurnHandle.pause()/resume()` | 暂停与取消语义不同，且不能污染 Run 生命周期 | RunStatus 保持 running；run_id/turn_id 不变，恢复后继续 |
| 程序中断后恢复 | 后置 | T06 不保存任何运行状态 | 会话持久化应与上下文工程统一设计 | 静态扫描无恢复存储；重启创建新 Run |
| 网络异常不立即丢失当前任务 | 调整 | 仅同进程暂停并等待 Retry/Cancel | 可重试，但不能伪装成跨进程恢复 | 网络暂停后同进程 Retry 完成或 cancel 终止 |
| 所有 ProviderError 自动重试 | 废弃 | 只有 Network/RateLimit 可暂停；其余失败 | 认证与协议错误不能靠重试解决 | Provider 错误分类测试 |
| Pending 类型化并关联 ID | 保留 | `PauseRequest/PauseResponse` | 防止响应串线 | wrong/stale/duplicate response 测试 |
| Pending 必须可落盘 | 废弃 | 只要求公开 payload JSON-safe | 本任务不定义持久化契约 | 无 checkpoint/store 类型 |

## 8. 核心协议与状态机

### 8.1 PauseKind

固定三种：

```text
user_requested
user_input_required
provider_unavailable
```

不得在 T06 增加：

```text
process_interrupted
recovery_review_required
checkpoint_failed
session_restored
```

### 8.2 PauseReason

固定原因值：

```text
user_requested
user_input_required
network_error
rate_limited
```

`PauseKind` 表示恢复动作类型，`PauseReason` 表示触发事实；两者必须形成合法组合，不得由 Interface 自由拼接。

| PauseKind | 合法 PauseReason | 合法恢复动作 |
| --- | --- | --- |
| `user_requested` | `user_requested` | `ResumeTurnResponse` 或 `turn.cancel()` |
| `user_input_required` | `user_input_required` | `UserInputResponse` 或 `turn.cancel()` |
| `provider_unavailable` | `network_error`、`rate_limited` | `RetryProviderResponse` 或 `turn.cancel()` |

### 8.3 PauseRequest

至少包含：

```text
pause_id
run_id
turn_id
kind
reason
iteration
created_at
tool_call_id（仅 user_input_required）
user_input_request（仅 user_input_required）
```

约束：

- `pause_id` 在一次 pending 期间稳定；恢复后再次暂停生成新 ID；
- `pause_id/run_id/turn_id` 非空；
- `user_input_required` 必须携带 `tool_call_id` 和问题；
- `provider_unavailable` 不携带 SDK exception、API key、请求头、原始响应或 traceback；
- 该模型是公开运行协议，不是磁盘 checkpoint；
- 不包含 workdir、model fingerprint、revision、schema migration 等持久化字段。

### 8.4 PauseResponse

使用带类型的联合模型：

```text
ResumeTurnResponse
UserInputResponse
RetryProviderResponse
```

所有响应必须携带：

```text
pause_id
run_id
turn_id
```

`UserInputResponse` 还必须携带 `tool_call_id` 和按 question ID 组织的 answers。取消不属于 resume response，统一调用既有 `turn.cancel()`。

Application/Core 必须拒绝：

- ID 不匹配；
- response kind 与当前 PauseKind 不匹配；
- 已解决后的重复响应；
- 上一个 pause_id 的陈旧响应；
- Turn 非 paused 时提交 resume；
- 未知 question ID、缺失必答项或非法选项。

### 8.5 AskUserQuestion

工具名固定：

```text
AskUserQuestion
```

该名称由 Core/Application 保留，并固定追加在当前 Turn 的普通 Tool definitions 之后：

- 不注册进普通 ToolRegistry；
- 不由 Integration 实现；
- 不通过手动 `execute_tool_calls()` 暴露；
- 只在自动 Agent Run 的 Provider ToolDefinition 中出现；
- 自定义 Tool 注册同名时直接失败；
- Agent Loop 判断 known/unknown tool 时必须把它视为 known；
- 它计入当前 iteration 的 ToolCall 数量限制，但不经过普通 ToolExecutor。

Tool description 必须明确：只有缺少继续执行所必需的用户事实或选择时才询问；不得用它代替 Permission 审批，也不得为可以安全推断的细节频繁打断用户。

一次调用：

- 1–4 个问题；
- question ID 在本次调用中唯一；
- header 与 question 非空；
- kind 只能是 `text`、`single_select`、`multi_select`；
- select 类型必须有 2–6 个唯一 label 的 options；
- text 类型不得携带 options；
- `allow_other` 只适用于 select；
- 不支持 `secret`；
- additionalProperties 必须拒绝。

答案稳定序列化为：

```json
{
  "answers": {
    "question_id": ["answer"]
  }
}
```

恢复后生成：

```text
ToolResultPart(
  tool_call_id=<原 call_id>,
  content=<稳定 JSON>,
  is_error=False
)
```

事件顺序固定为：

```text
ToolStarted(AskUserQuestion)
→ UserInputRequested
→ TurnPaused(user_input_required)
→ TurnResumed
→ ToolFinished(finished)
→ 后续 ToolCall / ToolBatchFinished
```

`ToolFinished` 与普通 Tool 活动事件不得包含用户答案正文；答案只进入原 ToolCall 的 ToolResult conversation。取消时不发 `TurnResumed`，而是以 cancelled ToolResult 闭合后进入唯一 `TurnCancelled`。

### 8.6 内存 continuation

不得保存或公开：

```text
Provider SDK 对象
Tool 实例
UI Widget
Exception / traceback
asyncio Task / Future / Lock / Event
Python 栈帧
```

Core 内部 continuation 只需表达当前活动 Turn 下一步所需的事实：

```text
stage = provider | tool_batch
iteration
provider_retry_pending
assistant_tool_message（仅 tool_batch）
tool_calls
completed_tool_results
next_tool_index
pending_pause
```

规则：

- continuation 只存在于当前进程内；
- 不提供 JSON round-trip 或 public export；
- Provider 用户暂停/网络暂停从当前 iteration 请求边界重试；
- Retry 不再次增加 iteration；
- Tool Batch 已完成的前序 Tool 不重放；
- AskUser 回答插入 `completed_tool_results` 后推进 index；
- Tool Batch 全部闭合后才提交完整 ToolResult message；
- terminal 后销毁 continuation 和 pending response waiter。

### 8.7 用户主动暂停时序

#### Provider 阶段

```text
pause() 设置 pause_requested
        ↓
取消当前 Provider CancellationToken
        ↓
Agent Loop 识别取消来源为 pause，而非 user_cancel
        ↓
丢弃未权威提交的 delta
        ↓
TurnPaused(user_requested)
        ↓
ResumeTurnResponse
        ↓
新 CancellationToken 重试当前 iteration
```

#### Tool 阶段

```text
pause() 设置 pause_requested
        ↓
当前 ToolCall 不被强制中断
        ↓
ToolResult 正常完成并保存在内存 continuation
        ↓
下一 ToolCall 开始前 TurnPaused(user_requested)
        ↓
ResumeTurnResponse
        ↓
从 next_tool_index 继续
```

若调用方需要立即停止当前 Tool，应使用 `cancel()`，不是 `pause()`。

### 8.8 网络暂停时序

- `NetworkError`、`RateLimitError`：进入 `provider_unavailable`；
- `AuthenticationError`、`ProviderConfigurationError`、`InvalidProviderResponseError`：进入 failed；
- `RetryProviderResponse` 创建新的 Provider CancellationToken；
- 同一 iteration 的 Retry/Resume 不重复发布 `IterationStarted`；
- 当前 iteration、conversation 和已完成 Usage 保持不变；
- 当前失败请求的 partial delta 与 Usage 不提交；
- 不自动 retry，不读取 `retry-after` 之外的 SDK 私有信息，不启动后台 timer。

### 8.9 取消优先级

- `cancel()` 是 terminal 请求；
- paused 时调用 `cancel()` 立即解决 pending，进入取消收口；
- pausing 与 cancel 竞争时，cancel 优先；
- AskUser pending 时 cancel 必须为当前及同批尚未执行 ToolCall 补齐确定性取消 ToolResult；
- terminal 后 pause/resume/cancel 均幂等拒绝，不再发事件。

## 9. Application 与 Interface 行为

### 9.1 Headless API

保留：

```python
application.create_run()
run.start_turn(prompt)
turn.events()
turn.result()
turn.cancel()
```

新增：

```python
turn.pause() -> bool
turn.pending_pause -> PauseRequest | None
turn.resume(response: PauseResponse) -> bool
```

语义：

- `pause()` 第一次有效调用返回 True；重复请求返回 False；
- `pending_pause` 只在 Turn 已进入 paused 后非空；
- `resume()` 只接受当前 pending 的一次有效响应；
- `events()` 仍是单消费者，并跨多个 pause/resume 周期保持同一事件流；
- `TurnPaused` 不是 terminal；
- `result()` 在 paused 时继续等待，只在 completed/failed/cancelled 返回；
- 恢复产生 `TurnResumed`，不产生第二个 `TurnStarted`；
- paused Turn 继续占用 Run 的活动槽位；
- Application 不提供任何 list/restore/persist API。

Application 内部允许使用 asyncio Future/Event/Queue 作为**当前进程中的协调细节**，但：

- 不进入 Core 公共模型；
- 不存入 Tool；
- 不暴露给 Interface；
- terminal/shutdown 时必须清理，不能泄漏 waiter。

### 9.2 TUI

#### Esc 路由与页面边界

Esc 不得实现为绕过当前页面状态的全局双击计数器。TUI 必须先由当前最上层交互上下文消费 Esc，再决定是否允许进入对话根页面的暂停手势：

```text
当前 modal / picker / 临时选择层
        ↓ 优先消费 Esc
对话根页面
        ↓ 仅此处识别双 Esc
TurnHandle.pause()
```

规则：

- `/model` 模型选择界面、Slash Command 选择层、AskUser 选项层和暂停动作菜单都拥有各自的 Esc 语义；
- Esc 被当前交互层消费后，不得继续冒泡到对话根页面；
- 关闭交互层、切换布局、切换焦点、进入或离开 paused 状态时，必须清空已有 Esc arm；
- 一次有效双 Esc 必须满足：两次按键都发生在对话根页面、属于同一活动 Turn、交互上下文版本未变化，并落在既有双击时间窗内；
- `/model` 中第一次 Esc 关闭模型选择界面并返回对话页面；该按键被完全消费，同时清空 Esc arm；
- 用户紧接着再按一次 Esc 时，它只能成为对话根页面的新“第一次 Esc”，最多显示暂停提示，不能与 `/model` 中的 Esc 组合触发暂停；
- 因此，从 `/model` 界面开始连续按两次 Esc，不得暂停当前 Turn；真正暂停还需要在返回对话页面后完成一组新的双 Esc；
- 相同规则适用于其他 modal、picker 和临时选择层，禁止因关闭界面而意外暂停 Turn。

实现上可以维护 Interface 私有的 `escape_arm` 与 `interaction_context_generation`，但它们不得进入 Application/Core，也不得成为 Run 或 Turn 状态的一部分。

#### 对话根页面双 Esc

- 仅当当前没有 modal、picker 或临时选择层，且焦点处于对话根页面时，第一次 Esc 执行现有 arm 提示；
- 满足同一交互上下文条件的第二次 Esc 调用 `TurnHandle.pause()`；
- 状态栏显示 `pausing…`；
- 到达安全边界后显示 `paused`；
- 弹出临时动作选择：Resume、Cancel current turn；
- 不新增 Slash Command；
- paused 时普通输入不能启动新 Turn。

#### AskUserQuestion

- 问题面板位于 prompt_toolkit 临时布局；
- 支持 text、single_select、multi_select、Other；
- 支持返回修改上一题、答案汇总和提交；
- Esc 关闭当前选择层，但不提交空答案；
- 提交后调用 `turn.resume(UserInputResponse(...))`；
- 显示内容只来自 Application 公开 PauseRequest；
- 不在 TUI 保存第二份权威 pending 状态。

#### 网络暂停

- 显示安全诊断，不显示 traceback 或 SDK 文本；
- 提供 Retry 与 Cancel current turn；
- Retry 调用 `turn.resume(RetryProviderResponse(...))`；
- 不提供“退出并保留任务”。

#### Ctrl+C、关闭与异常

- Ctrl+C 保持退出语义，不改成 pause；
- 有活动或 paused Turn 时，shutdown 尽力调用 `turn.cancel()` 并收口后台任务；
- 退出后任务不可恢复；
- 下次启动创建全新 Run，不显示恢复提示；
- 进程直接崩溃时不承诺补偿或保存；
- 文档必须明确这一边界。

TUI 继续满足：

```text
full_screen=False
mouse_support=False
不发送 CSI 3J
已写入 scrollback 的内容不回写
Interface 不导入 Core/Integration
```

### 9.3 非交互 CLI

`uthcode exec` 不提供交互式 pause/resume。

若事件流出现 `TurnPaused`：

- stderr 输出安全摘要：`generation requires interactive input` 或 `provider temporarily unavailable`；
- 立即调用 `turn.cancel()`，继续消费事件直到 `TurnCancelled` 或协调任务完成；
- 记录该 cancel 由非交互 pause 触发，因此最终映射为运行失败而不是用户 Ctrl+C；
- 不把当前流式文本写入 stdout 作为 final；
- 返回退出码 `1`；
- 不返回 75，因为进程退出后没有可恢复状态；
- Ctrl+C 仍返回 130；
- completed=0、failed=1、cancelled=130、usage/config error=2 保持不变。

### 9.4 程序重启

启动流程不得：

- 扫描状态目录；
- 询问是否恢复上次任务；
- 重建上次 run_id/turn_id；
- 回放 unresolved question；
- 读取任何 T06 恢复文件。

测试必须证明：退出旧进程后，新 Application 只创建新 Run，且用户目录/项目目录没有 T06 状态文件。
