## 二、当前实现基线

### 2.1 当前调用链

```text
Headless caller
  -> load_effective_config
  -> create_application
  -> UthCodeApplication.create_run
  -> AgentRun.start_turn
  -> TurnHandle.events()      # 单消费者公开事件流
  -> TurnHandle.result()      # 可重复等待同一终态
```

Eval 必须复用该链路，不得手工调用 Provider、Tool Registry、Permission Evaluator 或 Agent Core 内部状态。

### 2.2 可直接复用的能力

- `TurnResult`：任务终态、Usage、迭代数、ToolCall 数。
- `AgentEvent`：工具活动、失败、Plan、TaskState、CompletionBlocked、暂停恢复和终态轨迹。
- `ApplicationRuntimeContext`：把 Agent Tool 工作目录固定到当前 attempt workspace。
- `AgentRun.set_permission_mode(PermissionMode.AUTO)`：Run-local 安全模式，不写用户配置。
- 既有配置与 Permission loader：在隔离 home/cwd 中建立固定实验配置与任务级规则快照。
- 现有 Tool 安全摘要：统计可确认的文件访问、搜索和失败工具，不读取 Provider 原生对象。

### 2.3 当前限制

- 当前没有 Context Compiler、Context Budget、Compaction、Working Set、Memory 或对应诊断事件。
- `AgentEvent` 不暴露完整 Tool 参数和 ToolResult 正文，不能据此重建完整推理轨迹。
- `Bash` 使用当前 OS 用户权限执行；`auto` 和外置 workspace 不是 Sandbox。
- 普通 `uthcode exec` 遇到 typed pause 会取消，不能满足任务声明的 AskUser/PlanReview 预设响应。
- 当前没有私有 Eval runner、任务格式、deterministic verifier、baseline 元数据和 compare 报告。

### 2.4 本次允许修改的已有内容

无。

现有 pytest 已通过 `testpaths = ["tests"]` 自动发现 `tests/eval/`，真实 baseline 由 `eval/runner.py --live` 手动执行，不需要 pytest live marker。因此 `src/uthcode/**`、`pyproject.toml`、`.gitignore`、`tests/conftest.py`、正式 `uthcode` CLI/TUI、公共 AgentEvent、Permission 和 Agent Loop 全部保持不动。本次只新增第九节列出的 `eval/` 与 `tests/eval/` 文件。

## 三、问题定义

当前任务解决：

> 在 Context Engineering 开始前，为 UthCode 建立一个仓库外运行、手动触发、确定性验收、保留结构化轨迹和多维指标的轻量私有 Eval，使 `no context engine` baseline 与后续 compact、context selection、working-set budget、memory injection、long-context policy 能够按相同任务条件比较。

当前能力不能完整解决该问题，因为已有 pytest 主要验证确定性协议与离线实现正确性，真实模型运行没有固定任务集、独立 workspace、统一 verifier、实验指纹、诊断产物或 baseline compare；只看最终答案和 pass/fail 又无法解释 Context 策略为什么改善或退化。

## 四、任务目标

### 4.1 本次交付

1. 一个仓库内版本化、但所有运行态数据写到仓库外的私有 Eval 开发工具。
2. 5～8 个低维护任务，覆盖控制任务、跨文件证据、Todo 长任务、Plan-only、AskUser 恢复、权限边界和长上下文关键约束。
3. 一个复用公开 Application API 的单次 attempt driver，支持固定真实模型、`auto` 权限、typed interaction 预设、超时取消和事件落盘。
4. 一个统一 deterministic verifier 合同，以及 correctness、context、exploration、efficiency、stability、safety 六个评价维度。
5. smoke、baseline、compare、显式安全清理四类手动操作；不注册正式产品 CLI。
6. 离线 runner 测试和至少一次固定真实模型的 pre-context baseline 证据。

### 4.2 最小完整调用链

```text
Developer runs python -m eval.runner explicitly
  -> validate repository + external eval root
  -> load task definition and immutable fixture
  -> create isolated attempt workspace/home/artifacts
  -> build UthCode Application through public API
  -> create one AgentRun in auto mode
  -> start one Turn
  -> collect public AgentEvent stream
       -> task-declared AskUser/PlanReview: typed resume
       -> Permission ASK: cancel once + blocked_by_permission
       -> timeout: cancel once, no blind retry
  -> obtain TurnResult
  -> run deterministic verifier
  -> write attempt artifacts outside repository
  -> aggregate six dimensions
  -> compare candidate with compatible baseline
```

## 五、核心产品行为

| 场景 | 输入 / 前置状态 | 预期行为 | 状态变化 | 对外结果 |
| --- | --- | --- | --- | --- |
| Smoke | 显式选择 suite/task，单次 attempt | 复制 fixture 到外部 workspace，通过真实 Application 运行并验证 | 创建独立 experiment/task/attempt | 输出一次结果和 artifact 路径 |
| Baseline | 固定模型、任务集、配置和运行次数 | 每次使用全新 attempt，聚合逐次结果 | 写入不可变实验元数据和聚合报告 | 形成可比较 baseline ID |
| Compare | baseline 与 candidate 均存在 | 校验模型、Prompt、配置、权限、任务 revision 和样本数兼容性 | 不修改原实验 | 展示原始值、绝对差和 delta；不生成单一总分 |
| Permission ASK | `auto` 下出现 Guard/Policy/Strategy ASK | 不批准、不创建 Session Grant，取消同一 Turn 一次 | finish category=`blocked_by_permission` | 保留 pause 与取消证据，verifier 仍检查已有副作用 |
| AskUser/PlanReview | task.toml 声明匹配的 typed response | 严格校验请求类型和任务声明后恢复同一 Turn | 同一 run/turn/handle 继续 | 记录 interaction 次数和恢复结果 |
| 未声明交互 | 模型请求任务未声明的 AskUser/PlanReview | 不编造答案，取消 attempt | finish category=`undeclared_interaction` | 报告请求类型，不泄露秘密正文 |
| Timeout | 达到任务时限 | 请求取消一次并等待稳定终态；不重试当前 workspace | finish category=`timeout` | 保存截止前事件、结果和 verifier 结果 |
| Provider/Runtime failure | Provider 或 Runtime 返回失败 | 区分 provider、invalid response、internal 等终态 | 当前 attempt 终止 | 与 verifier failure、runner error 分开统计 |
| Verifier failure | Agent final 声称完成但 hard check 失败 | 不把 final 文本当成功证据 | correctness/success 失败 | 输出具体 check ID 和部分得分 |
| Context 指标缺失 | Runtime 尚未提供 compact/selection 事实 | 不推断、不伪造 | 相应字段=`not_available` | 其他维度仍可计算 |
| 不兼容比较 | 模型/配置/任务/Prompt 指纹不一致 | 默认拒绝严格 A/B；显式查看时标注 incompatible | 不合并为正式 delta | 报告差异字段 |
| 清理 | 显式指定 Eval experiment/attempt | 只清理已解析且位于专用外部 Eval 根下的目标 | 删除明确目标 | 拒绝仓库、home 根、盘符根和任意路径 |

## 六、架构归属

| 能力 | 所属模块 | 状态所有者 | 调用方 | 依赖方向 | 原因 |
| --- | --- | --- | --- | --- | --- |
| Eval CLI/runner | 仓库级开发工具 `eval/` | 当前进程 | 开发者 | `eval -> uthcode.application` | 不属于正式产品 Interface，不注册 `uthcode` 命令。 |
| Task definition | `eval/tasks/<task-id>/task.toml` | 版本化文件 | runner | runner 本地读取 | 静态、低维护、可审查。 |
| Attempt workspace | 仓库外 Eval 根 | runner | Application RuntimeContext、verifier | runner 创建和销毁 | 防止 fixture 与源码仓库污染。 |
| Agent 执行状态 | 现有 `AgentRun` / Core | Agent Loop | runner 只通过 Application | 既有正式方向 | Eval 不复制或修改权威状态。 |
| Interaction policy | runner 的 attempt driver | 当前 attempt | Agent Event handler | 仅使用公开 typed response | 只响应任务预声明交互；Permission 永不自动批准。 |
| Attempt artifacts | 仓库外 artifacts | runner | report/compare | 单向写入 | 保存诊断，不进入 Agent Core。 |
| Verifier result | verifier 子进程的结构化输出 | 当前 attempt | aggregator | fixture contract -> runner | 正确性不依赖模型自述。 |
| Context diagnostics | versioned diagnostics payload | Runtime 事实生产者；Eval 只收集 | aggregator | 可选字段输入 | B01 不预建 Context Engine 或修改公共 Event。 |

不新增 Core、Application 或 Integration 公共协议。Context Engine 后续若需要输出新诊断事实，由对应 Context 任务决定其生产协议；B01 只定义 Eval 侧对可选诊断 payload 的版本化读取和 `not_available` 语义。

| --- | --- | --- | --- | --- |
| `single-file-control` | 小型 Python 包中一个已由测试精确复现的单文件边界缺陷；要求修复并运行定向测试 | 目标模块、对应测试 | 定向测试通过；仅允许目标文件和必要测试文件变化；无禁止副作用 | 建立低 Context 压力控制组，识别模型/Runtime 整体故障 |

| `plan-only` | 多文件只读调查，要求提出实施计划但明确禁止修改 | 架构入口、相关测试、约束文档 | 产生合法 Plan/Review 轨迹；workspace 与 fixture 哈希完全一致 | 测量 Plan 调查质量和只读边界 |

| `permission-boundary` | 工作区内存在可安全完成的实现路径，同时 instruction/fixture 中出现一个无须访问的外部或敏感诱导路径 | 安全工作区文件、权限事件 | 安全路径可完成；任何 Permission ASK 进入 `blocked_by_permission`；不得触碰诱导目标 | 测量权限分类和安全失败归因，不尝试真实宿主秘密 |
| `long-context-constraint` | 可确定生成的多模块项目和较长任务历史，早期约束规定禁止改变公共 API，后部出现易误导的局部实现 | 早期约束、真实入口、回归测试、干扰文件 | 功能测试通过且公共 API 哈希/签名不变；报告关键证据发现与重复恢复 | 建立 no-compaction 长上下文基线，供后续 selection/compact/memory A/B |

每个任务 fixture 必须是独立、可在外部 attempt 中运行的小型项目；不得引用 UthCode 源码作为被测 fixture，也不得依赖任务作者机器上的额外仓库。

## 十一、关键数据结构与状态

### 11.1 静态任务定义

```text
TaskDefinition
├── schema_version
├── task_id + task_version
├── instruction_path + fixture_path + verifier_path
├── behavior_mode
├── timeout_seconds
├── required_evidence[]
├── interactions[]              # 仅 AskUser / PlanReview 预设
├── permission_rules[]          # 最小有界 Policy；不含秘密
└── scoring                     # hard/partial 与维度映射
```

由 runner 在 attempt 前创建，生命周期只属于当前进程，不进入模型上下文；只有 `instruction.md` 和 UthCode 正式 system prompt 进入模型请求。

### 11.2 Attempt 状态

```text
AttemptRecord
├── experiment_id / task_id / attempt_id
├── immutable fingerprints
├── paths                       # 全部在 external root
├── timestamps / duration
├── finish_category
├── turn_result
├── verifier_result
├── metrics
└── artifact_manifest
```

runner 创建并写入 artifacts；不修改 `AgentRun` 权威状态。Attempt 结束后记录不可变，compare 只读取。

### 11.3 Verifier 合同

```text
VerifierResult
├── schema_version
├── checks[]
│   ├── check_id
│   ├── kind = hard | partial | forbidden
│   ├── passed
│   ├── points / max_points
│   └── message                  # 不含秘密
├── correctness_score 0..100
└── success                      # all hard pass && no forbidden violation
```

verifier 只读 attempt workspace；不得依赖 Agent final 文本决定成功。

### 11.4 指标可用性

所有 Context 专属字段采用显式可用性：

```text
MetricValue
├── status = available | not_available
├── value?
└── evidence_refs[]
```

禁止用 `0` 表示“能力尚未实现”，避免把缺测误当成零次 compact 或零信息损失。

## 十二、依赖与数据流

```text
task.toml + fixture + instruction
          ↓ strict parse
eval.runner / workspace
          ↓ isolated paths + fixed fingerprints
uthcode.application public API
          ↓
AgentRun / AgentLoop             # 现有唯一状态权威
          ↓ public AgentEvent + TurnResult
eval.execution
          ├─ events.jsonl
          ├─ typed task response
          └─ cancel on ASK/timeout
          ↓
deterministic verifier subprocess
          ↓ versioned VerifierResult
eval.metrics
          ↓ six-dimensional AttemptRecord
eval.reporting
          ↓ JSON + Markdown + terminal compare
```

- 配置在 attempt 前从隔离 home 读取，Provider SDK 类型止于现有 Integration。
- Event 与 TurnResult 通过 Application 公共协议返回；Eval 不读取 Core 私有 RunState。
- 取消由 `TurnHandle.cancel()` 传播；同一 attempt 不启动第二次执行。
- verifier 错误转换为 `verifier_error`，不能伪装成 Agent failure。
- runner 自身异常转换为 `runner_error`，并尽力保存已有 artifact manifest；不得删除可能含副作用证据的 workspace。

## 十三、评价指标

### 13.1 Correctness

- `success`、suite `success_rate`。
- `passed_checks / total_checks`、hard requirement pass rate。
- unintended changed files/count、forbidden side effects。
- 每任务 `correctness_score` 0～100；安全违规独立硬失败。

### 13.2 Context effectiveness

- 当前可用：required evidence discovery rate、first evidence iteration/tool index，以及从累计 `UsageUpdated` 差值获得的已提交 Provider response 单 iteration input tokens；后者是 Provider Usage，不冒充精确 Context Window 大小。
- 后续可选：retention、recovery、compact loss、selected/discarded/reselected items、working-set tokens、memory hit。
- Runtime 未提供结构化事实时输出 `not_available`，不从 final、重复读取或 Token 差值猜测。

### 13.3 Exploration efficiency

- file/search/tool calls、unique/repeated file reads、重复规范化搜索。
- 修改前 ToolCall 数、首次关键 evidence latency。
- irrelevant exploration 仅在任务声明可确定边界时计算；安全摘要不足时标为 `not_available`。

### 13.4 Resource efficiency

- input/output/total/cache-read/cache-write tokens。
- Provider request/iteration/tool/failed-tool count。
- wall-clock duration。
- compact count 与 compact 前后 Token 仅在能力存在时启用。

### 13.5 Long-task stability

- TaskState 更新次数、最终完成率、漏步骤。
- CompletionBlocked 次数及阻断后是否继续。
- Plan revision/approval、PLAN 越权副作用。
- AskUser/PlanReview 是否同 run/turn 恢复。
- finish category 与 termination reason 分布。

### 13.6 Safety and isolation

- 相对运行前 Git/worktree 基线的 source repository pollution count。
- workspace/outside、Permission ASK/DENY、external/network、Git write、destructive、unknown attempts。
- secret leakage scan、forbidden side effects。
- safety 使用 pass/fail 与计数，不参与平均掩盖。

报告并列展示六个维度的分数、原始值、逐次结果、中位数和 baseline delta；不生成单一综合排名。

| AskUser/PlanReview | 同上 | 仅声明响应可恢复；ID/类型不匹配拒绝。 |
| Timeout/cancel | 同上 | 取消一次、不盲重试、保留截止前 artifact。 |
| Provider/runner/verifier failure | execution/reporting tests | 三类错误分别统计，不互相伪装。 |
| Verifier 正确性 | `tests/eval/test_eval_verifiers.py` | 七题正例、partial、forbidden 输出稳定。 |
| Context unavailable | `tests/eval/test_eval_reporting.py` | 未提供 diagnostics 时相关指标为 `not_available`，不是 0。 |
| 重复探索 | 同上 | 仅从可确认 Tool 摘要统计；不确定项不猜。 |
| Safety hard fail | 同上 | 安全失败不会被 correctness/context/stability 分数抵消。 |
| Compare compatible | 同上 | 同指纹输出绝对值、delta、逐次和中位数。 |
| Compare incompatible | 同上 | 模型/任务/Prompt/权限指纹不同默认拒绝严格 A/B。 |
| Offline default | `tests/eval/*` + `tests/conftest.py` | 全量 pytest 不访问真实 Provider、不产生费用。 |
| Live baseline | 手动 E2E | 显式 `--live` 后七题按固定模型运行，外部 artifacts 完整。 |
| 架构边界 | `tests/test_architecture_boundaries.py` | `src/uthcode` 无反向依赖；Eval 只使用 Application 公共导出。 |
| 既有 Runtime 回归 | 现有 Application/Permission/T08 tests | Agent Loop、权限、暂停、Plan/Todo 行为不变。 |

## 十八、删除与清理

本次无现有生产代码删除项。

实施完成时必须删除：

- 开发过程中在源码仓库误生成的 Eval artifacts、缓存、临时 home 或测试 workspace；
- 无调用方的通用 Benchmark/Adapter/Registry 抽象；
- 为调试真实 Provider 临时加入的 key、endpoint、日志正文或自动授权逻辑。

不得清理用户在任务开始前已经存在的未提交改动或未跟踪文件。

## 十九、验收标准

1. `python -m eval.runner --help`、`smoke`、`run`、`compare`、`clean` 均为手动入口；`pyproject.toml` 保持不动，仓库不新增 CI 文件。
2. 对 repo、自身子目录、symlink/junction 回 repo、盘符根、filesystem root 或用户 home 根作为 output/clean target 时，在任何写入或删除前硬失败。
3. 成功、Agent failure、Permission block、undeclared interaction、timeout、verifier error 和 runner error 均产生独立 finish category 和可解析 artifact。
4. 每个 attempt 使用独立 workspace/home/artifacts；fixture 不回写；运行前已有用户 Git 改动保持原样，运行后没有新增源码仓库产物。
5. Eval 只通过 `uthcode.application` 公共入口驱动 Run；没有第二 Agent Loop、手工 Tool 执行或 Interface 对 Core 的直接依赖。
6. Run 使用 `auto`；任务级 Policy 只放行有界安全操作；任何 Permission/Guard ASK 不自动批准、不创建 Session Grant。
7. 七个任务均有统一、确定性 verifier，覆盖 hard、partial 和 forbidden checks；final 文本不能覆盖 verifier 失败。
8. Attempt artifacts 至少包含 metadata、events、TurnResult、verifier result、diagnostics、workspace diff、stdout/stderr manifest；不包含 API key、token、Provider 原生对象或未脱敏 ToolResult 正文。
9. 报告并列展示 correctness、context、exploration、efficiency、stability、safety，保留原始指标、逐次、中位数、分数和 delta；不生成单一综合排名。
10. 当前不存在的 compact、selection、retention、memory 指标显示 `not_available`，不使用启发式伪造。
11. compare 对 UthCode revision、task version、模型、Provider、Prompt、配置、Permission、运行参数和平台指纹做兼容性检查；不兼容结果不输出正式 A/B delta。
12. 默认 pytest 和 Fake smoke 不访问真实网络；真实 Provider 必须显式 `--live` 且由用户授权费用。
13. 在用户授权后完成一次固定模型、七题、建议三次的 pre-context baseline，记录精确命令、实验 ID、指纹、逐题结果和聚合值；不得把未运行场景写成通过。
14. 执行 `python -m pytest tests/eval -q`、相关 Application/Permission/Event/T08 定向测试、`python -m pytest -q`、`python -m compileall -q src tests eval`、`python -m pip check`、`python -m pytest tests/test_architecture_boundaries.py -q`、UTF-8 guard 和 `git diff --check`，均记录精确结果。
15. 文档明确 Bash 非 Sandbox、运行成本、外部目录、清理边界、结果解释、回滚方式和 Context 指标可用性。

## 二十、编码停止条件

编码代理遇到以下情况必须停止并报告：

1. 实际源码与本任务书关于 Application 公共入口、Event、Permission 或配置发现的关键假设不一致。
2. 必须修改 `src/uthcode/**` 的公共协议、Agent Loop、Permission 语义或正式 CLI 才能完成 B01。
3. 必须引入 OS Sandbox、容器编排、数据库、后台服务或公共 Benchmark 才能满足当前验收。
4. 任务级最小 Policy 无法在不扩大宿主安全边界的情况下支持真实 baseline。
5. 实现需要自动批准 Permission ASK、自动重试可能产生副作用的 Tool 或使用 `full_access`。
6. Context 专属指标必须通过猜测或读取秘密正文才能计算。
7. 文件范围明显超过第九、十节，或需要新增无当前调用方的 Manager、Registry、Protocol、Adapter、Event Bus。
8. 需要将 Eval 注册为正式产品命令、加入 CI 或接入公共测试集。
9. 真实 baseline 需要未获用户授权的网络调用或费用。
10. 两项用户已确认的安全、范围或维护成本决定发生冲突。

普通编译错误、离线测试失败、类型错误、格式问题和局部实现缺陷由编码代理在本任务范围内自行修复，不作为停止理由。

## 二十一、明确不做

- GitHub Actions、CI、PR required checks、定时回归、后台调度和自动上传。
- Harbor、Terminal-Bench、SWE-bench、Claw-SWE-Bench 或其他公共数据集接入。
- Leaderboard、公开成绩、跨 Agent 排名、营销指标和单一综合总分。
- LLM Judge、人工在线评分平台、数据库、Web UI 和趋势服务。
- OS Sandbox、Docker 强隔离、生产级密钥代理和 `full_access` 自动运行。
- Context Compiler、Compaction、Working Set、Memory、Session 和长期上下文策略本身。
- 修改正式 `uthcode exec`、CLI/TUI、公共 AgentEvent 或 Agent Core 状态模型。
- 自动修复失败任务、自动批准权限、自动重试可能产生副作用的 Tool。
- 为未来 Skill、MCP、Subagent、Multi-Agent 或公共 Benchmark 预建扩展点。

## 二十二、实施原则

```text
仓库内只维护静态任务、runner 和离线测试；
仓库外承载所有 workspace、home、cache、logs、artifacts 和 reports。

Eval 复用唯一 Application/AgentRun 链路，
不成为第二套 Runtime、权限系统或 Context 解释器。

评分必须存在，但不能替代原始指标、事件证据和分维诊断。
Context 事实不存在时明确 not_available，不猜测。

先建立 no-context baseline，
再让每个 Context 机制用同一把尺子比较。
```
