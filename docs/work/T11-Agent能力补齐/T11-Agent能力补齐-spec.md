## 背景

当前 Agent 已具备文字 ReAct、权限、会话历史与 Desktop，但尚不能完成附件、视觉观察、联网取证和跨 Turn 长进程验证的统一闭环。需求来源为 [T11-Agent能力补齐.md](T11-Agent能力补齐.md)，其中九项决定已确认，本文不重新打开这些决定。

## 目标

让同一正式 Agent 从截图或文档开始，定位代码与来源，修改并运行验证，消费失败日志和图片，再交付可打开的文件。正常长任务不受累计轮数上限约束；有证据的异常先纠偏后截停，未知副作用立即停止自动推进。

## 非功能要求

- 保持模块化单体和 Interface 可替换；无界面链可独立运行，第三方类型和 OS 资源不进入 Core。
- 每次工具调用有终态结果，批次严格顺序；失败、实际副作用、持久化和显示分别表达，保存或显示失败不得重做写入。
- 输入、输出、解析、日志和派生缓存有界且可取消；正常运行淘汰失效内容，已提交原图保留为会话资料。
- 权限审批仍是应用授权，Bash 仍是当前 OS 用户权限下的非沙箱执行。搜索秘密仅允许用户级可信配置；项目不得注入凭据、重定向服务或提升权限。
- 进度只作观察，受控日志先脱敏限量再展示；不将图像字节、原始 SDK 载荷或秘密写入历史、事件和评测产物。
- 兼容旧文字业务数据只做结构必要迁移；不保留双轨执行、长期双写或未来占位框架。
- Windows 原生 PTY 与打包读取属于必需能力；真实模型、联网和官方评分证据不能由替代测试冒充。

## 设计骨架

Desktop/CLI/TUI 经 Application 输入用例进入同一 Core Loop。Application 组合会话资料、Provider 和工具适配；Core 只拥有领域内容与运行状态。附件与工具图片共享内容表达，经真实 Provider 请求送入模型。

原始附件属于会话资料，缩略图、解析文本和页图属于可重建派生内容。历史与 Context 沿用现有权威链；图片参与预算和能力预检，压缩保留来源以便再次读取。模型能力不支持或未知时阻止含图请求，保持草稿和既有模型；不静默降级。

活进程属于会话 Application，在同一程序内跨 Turn 保留，导航不终止。成功 Turn 保留后台进程，取消或异常截停回收本 Turn 启动的进程，显式关闭回收全部所属资源；进程输入独立经过权限，不自动重放。Desktop 展示有界日志并可读取后续，TUI 只接入必要合同与终态。

网络工具只调用已批准搜索服务或显式公开地址；抓取跳转重新经过实际目标权限。文件修改先统一预检，再按单目标提交并报告准确部分结果；Git 专用能力只读。异常检测观察有限窗口内的失败和无效循环，先提供具体纠偏再截停；合法等待和新证据不误判，无隐藏累计预算上限。

Settings 沿用可信配置与活动快照，改变只在安全边界生效，不重启已有进程。产物经 Application 验证后由 Desktop 打开/定位；评测复用正式 Headless，外部评分系统负责判分。
