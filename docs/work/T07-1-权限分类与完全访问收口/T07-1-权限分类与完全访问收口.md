## 一、Spec

### 1. 背景

当前 Windows Bash 分类器不能识别 CMD 的 `cd /d <path>` 静态目录切换，并把普通括号命令组一律标记为不透明嵌套执行。模型常生成 `cd /d ... && (...) | ...`，因此本应属于只读、工作区内的命令会退化为 `UNKNOWN`，同时生成 `nested-execution` Guard 事实。

当前权限矩阵又规定任何内置 Guard ASK 在 `full_access` 下仍然强制确认，且 Guard 审批不提供当前 Run 授权。分类误报和过重的完全访问语义叠加后，用户即使主动选择 `full_access`，仍会对普通调查命令反复执行 `Allow once`。

本任务同时修复分类缺陷并替换完全访问语义。外部产品只用于校准用户体验边界：OpenAI Codex 将 OS Sandbox 与 Approval Policy 分开控制；Claude Code 的 bypass 模式跳过普通权限检查，但仍尊重显式 ask/deny，并保留极小的根目录/Home 删除断路器。UthCode 当前没有 OS Sandbox，因此只在完全访问模式中额外保留磁盘/卷与裸设备写入这类同等级本机灾难操作。

参考：

- [OpenAI Codex Agent approvals & security](https://learn.chatgpt.com/docs/agent-approvals-security)
- [Claude Code permission modes](https://code.claude.com/docs/en/permission-modes)

### 2. 目标

- 正确识别 Windows CMD 的静态 `cd /d <path>`，并按复合命令顺序计算物理目录范围。
- 区分 CMD 普通括号命令组与真正不透明的命令替换、嵌套 Shell 或间接执行，消除只读调查命令的 `nested-execution` 误报。
- 让 `full_access` 跳过内置普通 Guard、普通 Policy 与 Strategy，不因敏感读取、远程脚本管道、提权、UNKNOWN 或不透明嵌套执行产生内置确认。
- 保留用户和项目显式配置的 Guard ASK/DENY；完全访问模式不能覆盖用户主动声明的边界。
- 引入极小、明确、不可被普通允许规则覆盖的灾难性 circuit breaker；三种模式均要求单次确认。
- 代码与测试通过后，直接以新事实改写当前治理和 `docs/context` 文档，不并列保留已经失效的旧口径。

### 3. 能力清单

#### Task 1 — Windows 静态导航与命令组分类

把 CMD 的 `/d` 视为 `cd`/`chdir` 的已知静态选项；仅在目标是单个、不含展开或通配符的字面路径时参与只读分类和物理范围演算。普通 CMD 括号命令组必须继续拆解其中可见命令，不能仅因外层 `(...)` 产生 `nested-execution`。

真正不透明的命令替换、反引号、Shell `-c`、`cmd /c`、`xargs`、`find -exec` 等仍保持保守事实。无法可靠解析的命令仍可为 `UNKNOWN`，但 `UNKNOWN` 本身不是灾难性事实。

#### Task 2 — `full_access` 与灾难性断路器

将内置 Guard 分为普通 Guard 与强制 circuit breaker，同时保持唯一权限评估链。`full_access` 跳过内置普通 Guard、普通 Policy 与 Strategy；用户和项目显式 Guard ASK/DENY 继续生效。

circuit breaker 仅覆盖：

- 递归删除 POSIX 文件系统根、Windows 盘符/共享根；
- 递归删除当前用户 Home/Profile；
- 格式化、清空或重建磁盘与卷；
- 向裸磁盘或块设备写入。

circuit breaker 在 `default`、`auto`、`full_access` 下均为 ASK，只提供 `Allow once` 与 `Reject`，不形成 Session Grant。普通规则的 ALLOW 不得绕过 circuit breaker；匹配到更严格的用户/项目显式 DENY 时仍以 DENY 结束。

以下现有事实不是 circuit breaker，在 `full_access` 下不得仅因内置检测而询问：工作区整体删除、Git destructive 操作、提权包装、远程脚本管道、fork bomb、关键进程终止、递归权限修改、敏感资源读取、命令替换、括号分组、嵌套 Shell、UNKNOWN 与无法完整解析的语法。

### 4. 非功能要求

- Bash 仍是当前 OS 用户权限下的未沙箱化进程执行；本任务不增加 OS Sandbox。
- Tool preflight 继续在真实执行前产生可信、展示安全的 Action；模型不能声明 effect、scope、Guard 等级或 circuit breaker。
- 保持 `Tool prepare -> fixed runtime hook -> Permission -> execute` 的唯一正式链路，不新增第二 evaluator、绕过入口或 Interface 权限逻辑。
- 分类器保持保守、可测试，不以完整 Shell/PowerShell/CMD AST 为前置，也不因本任务扩张为通用命令解释器。
- circuit breaker 的类别必须由结构化、段级可信事实产生；不得依赖展示摘要中的任意文本搜索。
- 现有秘密脱敏、参数校验、工具注册、OS 权限和第三方权限边界不变。

### 5. 设计骨架

```text
normalized ToolCall
  -> Tool preflight
     -> Bash segment scan
        -> effect + physical scope
        -> ordinary guard facts
        -> catastrophic circuit-breaker facts
  -> fixed Runtime Hook
  -> one PermissionEvaluator
     -> catastrophic circuit breaker
        explicit stricter DENY -> DENY
        otherwise match -> ASK (all modes, ONCE/REJECT)
     -> configurable user/project Guard
        ASK/DENY -> terminal in all modes
        ALLOW -> continue
     -> full_access
        -> ALLOW; skip built-in ordinary Guard, Policy, Strategy
     -> default/auto
        -> built-in ordinary Guard -> Policy -> SessionGrant/Strategy
  -> execute once or controlled ToolResult
```

内置 circuit breaker 必须有可信、不可由普通规则伪造或降级的分类属性。该属性只由生产代码创建，权限 TOML 不开放对应字段；不得通过 rule ID 字符串前缀、展示摘要内容或来源名称猜测强制等级。

### 6. 已确认决策

- D1：采用方案 A。`full_access` 跳过内置普通 Guard，但保留用户和项目显式 Guard ASK/DENY。
- D2：采用方案 A。灾难性断路器只保留根目录/Home 递归删除、磁盘/卷破坏和裸设备写入。
- D3：采用方案 A。断路器在所有模式中 ASK，只提供单次允许与拒绝。
- 历史 T07 工作包是冻结历史证据，不回写；AGENTS、README、Context 与生产注释/模板中的当前旧口径直接删除或改写。

### 7. 能力欠账

无。本任务修复当前分类缺陷并替换已冻结但不符合当前产品选择的权限语义，不依赖后置能力，也不回补 `docs/OutstandingDebtList.md` 中的既有条目。

### 8. Out of Scope

- OS、容器、路径、网络或系统调用 Sandbox。
- 完整 Bash、POSIX Shell、CMD 或 PowerShell AST。
- AI 权限分类器、后台安全模型、动态风险评分或自动学习。
- 新权限模式、`full_access` 持久化、Session Grant 持久化或持久 Session。
- 修改项目配置不能启用 `full_access` 的现有边界。
- 为普通 Guard ASK 增加 Session Grant，或新增“本次命令族永久允许”。
- Skill、MCP、Subagent、动态 Tool/Hook Permission API。
- 修改归档 T07/T08/T08-1 的冻结文档以伪装历史决定从未存在。

### 9. 验收标准

1. `cd /d <inside> && git log/status` 在 Windows 语义下分类为 READ/INSIDE；字面外部路径为 READ/OUTSIDE；动态、缺失或歧义目标保持 UNKNOWN。
2. `(for ... do type ...) | find ...` 这类可见 CMD 命令组不产生 `nested-execution`；真实命令替换和间接执行仍产生保守事实。
3. 分类聚合继续保证任意真实 WRITE、DESTRUCTIVE 或 EXTERNAL 片段不会被只读前缀掩盖。
4. `full_access` 对敏感读取、提权、远程脚本管道、fork bomb、关键进程终止、递归权限修改、嵌套执行和 UNKNOWN 均不因内置普通 Guard 请求确认。
5. 用户/项目显式 Guard ASK/DENY 在 `full_access` 下仍分别 ASK/DENY；普通 Policy 与 Strategy 仍被跳过。
6. 根/Home 递归删除、磁盘/卷破坏和裸设备写入在三种模式均 ASK，且只有 ONCE/REJECT；普通 ALLOW 规则不能覆盖，更严格显式 DENY 仍生效。
7. circuit breaker 正反例覆盖 POSIX 与 Windows；危险命令只验证 preflight/evaluator，不实际执行。
8. 正式 Headless/Application/TUI 权限链的 decision、pause choices、执行次数和 ToolResult 闭合一致，无 Interface 旁路。
9. AGENTS、README、权限模板/注释和所有命中的 `docs/context/**` 只保留新口径；归档工作包保持不变。
10. 定向测试、架构测试、全量测试、compileall、pip check、UTF-8 guard 与 diff check 通过。

### Task 1 — Windows 静态导航与命令组分类

- 修改 `src/uthcode/integrations/tools/process_tools.py`：支持 `cd`/`chdir` 的单个 `/d` 选项与字面目标，复用现有物理路径范围演算。
- 收紧 `_scan_bash_command` 对括号的语义：CMD 普通命令组不再等同不透明嵌套执行，同时保留命令替换、反引号与现有间接执行识别。
- 保持复合命令 effect 优先级、连接符顺序、敏感内容操作类型与展示脱敏不回归。
- 修改 `tests/test_builtin_process_tool.py` 与必要的分类测试，先加入旧实现失败的 `cd /d` 和 CMD 分组回归，再做最小实现。
- 依赖：无。
- 完成边界：不实现完整 Shell AST，不把未知语法猜成 READ，不执行测试中的危险命令。

### Task 2 — `full_access` 与强制 circuit breaker

- 修改 `src/uthcode/core/permission.py`：为 Rule 增加最小可信强制等级，调整唯一 evaluator 顺序，使 circuit breaker、显式 Guard 与 `full_access` 新矩阵可独立证明。
- 强制等级采用安全默认值，且不改变普通调用方构造现有 Rule 的行为；不新增第二 evaluator、全局状态或 Integration 反向控制。
- 修改 `src/uthcode/integrations/permissions.py`：拆分内置普通 Guard 与 circuit-breaker Guard；权限 TOML parser 必须拒绝外部声明强制等级，默认模板删除旧“所有 Guard 都在所有模式生效”的口径。
- 修改 `src/uthcode/integrations/tools/process_tools.py`：只为已确认四类灾难操作产生 circuit-breaker 事实；清理不再属于断路器的事实与无真实消费者的死路径。普通模式仍可通过普通 Guard 保护必要的高风险/敏感行为。
- 修改 `tests/test_permission.py`、`tests/test_permission_rules.py`，覆盖三模式矩阵、来源优先级、普通 ALLOW 不覆盖断路器、显式 DENY 更严格、外部配置不能伪造强制等级。
- 依赖：Task 1。
- 完成边界：不持久化 `full_access`，不减弱工具注册、参数校验、Hook、OS/第三方权限或敏感摘要保护。

### Task 3 `[接入主流程]` — 正式权限链与交互收口

- 核对 `src/uthcode/core/agent.py`、`src/uthcode/application/runs.py`、`src/uthcode/application/tools.py` 与 TUI 权限投影，确保新 decision 仍只经正式 Permission pause/resume 链执行。
- 仅在真实需要时窄改上述文件；circuit breaker ASK 继续投影 `ONCE/REJECT`，用户/项目显式 Guard ASK 同样不提供 Session Grant。
- 修改 `tests/test_permission_delivery.py`、`tests/test_agent_interaction.py`、`tests/test_application_runs.py` 和必要 TUI 测试，覆盖正式入口与同一 ToolCall exactly-once。
- 删除已被替代的“任意内置 Guard 在 full_access 下强制 ASK”生产分支、测试夹具和重复 helper，不保留兼容开关。
- 依赖：Task 2。
- 完成边界：Headless、CLI/TUI 共享相同 Core/Application 语义；Interface 不识别 Guard 等级或自行放行。

### Task 4 `[端到端验证]` — 分类与完全访问真实组合验收

- 新增 `tests/test_t07_1_e2e.py`，使用正式 Application、离线 Scripted Provider、真实 Tool preflight/evaluator 与临时工作区。
