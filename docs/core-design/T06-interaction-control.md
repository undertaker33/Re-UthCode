# T06：让运行过程可以被控制

长任务不总能一次跑到底。模型可能需要补充信息，Provider 可能暂时不可用，工具可能需要批准，用户也可能主动暂停。工程化 Agent 必须把这些情况建模为运行状态，而不是临时弹窗。

## 暂停是状态，不是重新开始

UthCode 支持用户主动暂停、询问用户、Provider 重试、权限审批和计划审阅等 typed pause。它们都遵循同一模式：

```text
running
  → 产生 PauseRequest
  → paused
  → 接收匹配的 PauseResponse
  → resumed
```

恢复时仍使用原来的 Turn、执行对象和事件流。已经完成的 Provider 响应、工具预检与状态更新不会被重做。

## 为什么响应必须精确匹配

每个暂停都有自己的 ID，并绑定 Run 与 Turn；工具审批还绑定具体 Tool Call。这样，迟到的旧响应不能误解锁另一个操作，Interface 也不能用一份通用“继续”信号跳过当前等待的问题。

## 暂停与取消是两种语义

暂停表示“保留现场，稍后继续”，取消表示“结束当前 Turn”。取消优先于尚未处理的审批或恢复响应，并且可以重复调用而不产生第二次终止。

正在执行的普通工具不会因为协作式暂停被强杀，因为系统无法假定它是否已经产生副作用。取消 Bash 时会尝试终止进程树，但这仍不等于能够回滚已发生的外部变化。
