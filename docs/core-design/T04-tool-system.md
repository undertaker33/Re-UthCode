# T04：工具是 Agent 的行动接口

只有模型和上下文的系统仍然只是一个顾问。工具把模型的决定转换成对环境的观察和行动，让 Agent 能搜索代码、读取文件、写入修改和运行测试。

UthCode 默认提供 `ReadFile`、`WriteFile`、`EditFile`、`Glob`、`Grep` 与 `Bash`。前三组主要面向项目文件，`Bash` 则以当前操作系统用户权限启动进程。

## Tool Call 不是直接函数调用

模型产生的工具名和 JSON 参数不能直接执行。UthCode 使用一条受控链路：

```text
Tool Call
  → 查找注册工具
  → 校验并准备参数
  → 生成权限事实
  → 权限判断
  → 执行
  → Tool Result
```

“准备”与“执行”分开很重要。系统可以先解析真实目标、规范化路径并判断影响范围，再决定是否运行；用户审批后也无需重新猜测或重复预检。

## Observation 必须与 Action 对应

模型给出的每个 `tool_call_id` 都必须收到一个 Tool Result。即使工具不存在、参数错误、权限被拒绝或执行失败，结果仍会以受控错误返回模型。

普通 Tool Batch 按 FIFO 顺序执行。一个调用失败不会让其余调用凭空消失，也不会破坏消息协议的闭合。模型可以观察错误，再选择修正参数、换用工具或向用户解释。

## 对模型可见，不等于对日志公开

工具正文需要进入对话轨迹，否则模型无法继续推理；界面活动则只展示脱敏、截断的摘要。UthCode 将“Agent 工作所需的信息”和“用户活动记录适合展示的信息”分开处理。
