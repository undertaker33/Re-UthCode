# T05：用 ReAct Loop 闭合感知与行动

Agent 的关键不是调用一次模型，而是让模型能够反复经历“判断—行动—观察”。UthCode 用显式、顺序可读的 ReAct Loop 完成这个闭环。

```text
用户目标
  → 模型判断
  → 文本回答，结束
       或
  → Tool Call
  → 工具执行
  → Tool Result 加入上下文
  → 再次请求模型
```

## 一次 Turn 可以包含多次模型请求

Turn 表示用户的一次任务，不等于一次 Provider 调用。模型可能先搜索文件，再读取代码、编辑内容、运行测试，最后才生成回答。这些步骤都属于同一个 Turn，并共享同一份逐步增长的状态。

每次 Provider 返回后，Loop 先验证响应并累计 Usage。如果得到最终文本，就尝试完成 Turn；如果得到 Tool Call，就执行完整批次，把结果组成 Tool Message，再进入下一次迭代。

## 状态只能有一个权威写入者

UthCode 让 Agent Loop 成为 `RunState` 的唯一写入者。Provider 只返回模型结果，Tool 只返回执行结果，Permission 只返回决定，Interface 只返回控制响应。

这个约束避免出现几份互相竞争的“当前状态”。事件是状态变化的观察投影，不是第二个状态仓库；界面丢失或替换也不会改变 Core 对任务的判断。

## Harness 负责把失败变成可处理信号

无效 Provider 流会使 Turn 失败；普通工具错误则形成 Tool Result，让模型有机会修正。迭代次数、单批工具数和连续未知工具都有上限，避免模型在无效轨迹中无限循环。

至此，一个最小 Agent Core 已经成立。接下来的问题是：当运行持续较久，用户怎样在不破坏状态的前提下介入？
